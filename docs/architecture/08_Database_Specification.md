# Database Specification

## Purpose

This document defines the complete database specification for the project.

It serves as the implementation reference for generating Laravel migrations and Eloquent models.

This document should be used together with the following files:

- CURRENT_DATABASE.json
- FINAL_ERD.dbml
- DATABASE_ARCHITECTURE.md
- BUSINESS_RULES.md

The JSON file represents the current implementation.

This document represents the target implementation.

The AI must compare both and generate only the necessary database modifications.

---

# General Standards

## Primary Keys

Every table must use:

- id
- bigint
- auto increment

---

## Foreign Keys

All relationships must use foreign key constraints.

Use cascading updates whenever appropriate.

Avoid cascading deletes unless explicitly required.

---

## Timestamps

Every table must contain

- created_at
- updated_at

unless otherwise specified.

---

## Naming Convention

- Singular model names
- Plural table names
- snake_case columns
- Laravel naming conventions

## users

### Purpose

Stores authentication credentials for administrators and teachers.

### Columns

| Column | Type | Nullable | Notes |
|---------|------|----------|------|
| id | bigint | No | Primary Key |
| teacher_id | bigint | Yes | FK → teachers.id |
| username | varchar(100) | No | Unique |
| email | varchar(100) | No | Unique |
| password | varchar(255) | No | Hashed Password |
| role | enum | No | System Role |
| status | enum | No | Active / Inactive |
| last_login_at | timestamp | Yes | Last successful login |
| created_at | timestamp | No | |
| updated_at | timestamp | No | |

- belongsTo Teacher

# Migration Notes

The existing implementation already contains multiple tables.

Do not recreate existing tables.

Compare the current database against the final architecture.

Generate only the required Laravel migrations.

Maintain backward compatibility with the existing attendance system.

Do not remove classroom attendance functionality.

Do not remove gate attendance functionality.

Generate migrations in logical order to avoid foreign key conflicts.

Example order

1. Create lookup tables
2. Modify existing tables
3. Create grading tables
4. Add foreign keys
5. Add indexes

---

# Implementation Rules

When generating migrations,

- Preserve existing data.
- Preserve existing relationships.
- Add only missing columns.
- Add only missing tables.
- Do not rename tables unless explicitly instructed.
- Follow Laravel 13 migration conventions.
- Use proper foreign key constraints.
- Use indexes where appropriate.
- Generate reversible migrations.
