1. EXECUTIVE SUMMARY
================================================================================

The system has three well-developed but unevenly wired subsystems:

- QR ATTENDANCE: a functional gate-scan pipeline (ScanController -> ScheduleResolver
  -> AttendanceLog/FlaggedScan/GateScanMail) exists, but it is GUARD-DRIVEN,
  UNAUTHENTICATED at /api/scan, contains several verified bugs (missing enum value,
  nested response, no attribution), and has NO analytics, NO student self-scan flow,
  NO teacher verification layer, and ZERO tests.

- SF1 BULK IMPORT: a complete Upload -> Parse -> Validate -> Import pipeline exists
  (BulkImportService, SpreadsheetParser, ImportRowValidator, ImportProcessor,
  bulk_imports / bulk_import_issues) and is reusable. The ROW-LEVEL PREVIEW step is
  missing, there are ZERO tests, and processing is SYNCHRONOUS.

- GRADING: the data schema and a computation engine exist but are ORPHANED:
  GradingService + SubjectWeightResolver (DepEd transmutation) are referenced by
  NO controller, route, or test. It is HARD-CODED to Q1-Q4 (seeded in a migration),
  has NO trimester support, NO teacher-configurable weights, NO 100% validation,
  and ALL grading views are missing. This is the highest-risk area given the
  stated deadline.

ANALYTICS (QR and Grading) are entirely NOT IMPLEMENTED. There is no chart library,
no aggregation queries, and /dashboard is a hardcoded placeholder.

3.2 CURRENT FLOW (gate - ScanController::scan)
----------------------------------------------
1. Validate QR code -> QrCode::with('student.guardian')->where('code')->where('is_active',true)
   -> 404 if invalid.
2. Resolve active enrollment (status='active') -> loadMissing('sectionModel') -> 404s.
3. ScheduleResolver::resolve(section->level, enrollment->session_type, time)
   -> 400 outside window.
4. Last scan today for that session -> state machine IN->OUT->RE_ENTRY->RE_EXIT->RE_ENTRY...
5. Hard cutoffs: IN window (in_start..in_end), OUT window (out_start..out_end).
   RE_ENTRY/RE_EXIT have NO window validation.
6. $isLate = scanType==='IN' && now > late_threshold.
7. AttendanceLog::create in a transaction. scanned_by_user_id and device_id are NEVER set.
8. Flags: late_arrival (IN + late), invalid_checkout (OUT without valid IN).
   NOTE: 'invalid_checkout' is NOT in the flagged_scans.flag_type enum -> REQUIRES REVISION.
9. Guardian email: EmailLog row + synchronous Mail::send(GateScanMail).
   BUG: the success JSON response is nested inside if($guardian && $guardian->email),
   so a student without a guardian email gets an EMPTY 200 with no payload.

3.3 CURRENT BUSINESS RULES
--------------------------
- Scan types: IN / OUT / RE_ENTRY / RE_EXIT (enum on attendance_logs).
- Sessions: morning / afternoon enum on attendance_logs AND enrollments.
  whole_day is validated in forms but NOT present in the DB enum.
  Migration 2026_06_19_204412_update_session_type_enum_on_enrollments_and_schedule_configs.php
  is a NO-OP (both up()/down() contain only '// No action needed.').
- Lateness = flag only (no PRESENT/LATE status column on attendance_logs).
- Guardian notified on every scan type, synchronous, status tracked in email_logs.
