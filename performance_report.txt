Performance Investigation Report
===============================

Route: /teacher/student-management

Summary:
- The slow page is not caused by a large number of queries (no N+1 issue detected).
- The main bottleneck is latency from remote PostgreSQL and database-backed session handling.

Evidence:
- Logged 5 SQL queries during a real Laravel request.
- Total DB time measured: 4314 ms.

Query timing breakdown:
1. select * from "users" where exists (select * from "teachers" ...) and "users"."deleted_at" is null limit 1
   - ~2508 ms
2. select * from "teachers" where "teachers"."user_id" in (16)
   - ~404 ms
3. select * from "sessions" where "id" = ? limit 1
   - ~400 ms
4. select * from "sessions" where "id" = ? limit 1
   - ~400 ms
5. insert into "sessions" (...) values (...)
   - ~587 ms

Additional latency evidence:
- A direct PostgreSQL probe using SELECT now(); took ~1.920 seconds.

Configuration notes:
- config/session.php uses 'driver' => env('SESSION_DRIVER', 'database').
- Database sessions are adding multiple remote DB round-trips on each request.

Root cause:
- Remote DB latency is the dominant factor.
- Database-backed sessions exacerbate the problem by generating additional session read/write queries.

Recommendation:
- Switch SESSION_DRIVER to 'file' or 'redis' for local performance testing.
- If the remote Postgres DB remains required, move session storage off the remote DB or use a faster local cache store.
