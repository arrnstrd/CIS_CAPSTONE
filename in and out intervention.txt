Redesign the existing **School Admin Attendance Analytics** feature into a **School Admin IN and OUT Analytics** dashboard.

The feature is specifically for analyzing student **Time In, Time Out, Late Arrivals, and Missing Time Out** patterns across the school.

The goal is to make the page an immediately useful analytics dashboard. It should contain meaningful data and visualizations on initial load without requiring the admin to select a date, grade level, or other global filter first.

---

# 1. Sidebar Rename

Rename the existing sidebar item:

`Attendance Analytics`

to:

`IN and OUT Analytics`

Use this exact naming throughout the School Admin interface where appropriate.

---

# 2. Remove the Current Analytical Scope Container

Remove the existing **Current Analytical Scope** container at the top of the page.

Do not replace it with another global filtering container.

There should NOT be a requirement for the admin to first choose:

* Date
* Grade level
* Section
* Other global scope

before the analytics become visible.

The dashboard should already display meaningful analytics when opened.

---

# 3. Default Analytics Behavior

When the page first loads:

* Charts should already contain data.
* Tables should already contain data.
* Summary statistics should already contain data.
* The page should not appear empty simply because no filter has been selected.
* Do not default the analytics to "Today".

For time-based analytics, use this hierarchy:

### Default

Show a **3-month overview** when sufficient data exists.

### Fallback

If the most recent 3 months contain insufficient or no usable attendance data, automatically fall back to the **full school year**.

The purpose is to ensure that the dashboard always provides meaningful historical context.

The admin can still change the date range afterward.

---

# 4. Filtering Philosophy

Filters should be **isolated to the visualization or table they control**.

Do not create one global filter that changes the entire page.

Each chart/table can have its own relevant filters inside its own container.

For example:

`Daily Scan Velocity & Movement Trends`
→ Date filter + metric pills

while:

`Section Attendance & Late Entry Breakdown`
→ Section/grade-related filters if applicable

while:

`Multiple Late Arrivals Follow-Up Registry`
→ Its own relevant filtering/sorting controls

Filters must only affect their associated visualization/table.

---

# 5. Summary Statistics

The page should immediately begin with useful summary statistics for the selected/default analytical period.

Include meaningful metrics related to:

* Total Time In records
* Total Time Out records
* Late arrivals
* Missing Time Outs
* Attendance/scan completion where supported
* Other relevant existing IN/OUT metrics

The statistics should reflect the current analytical period used by the dashboard.

Do not require the admin to select a date before showing these.

---

# 6. Daily Scan Velocity & Movement Trends

Keep **Daily Scan Velocity & Movement Trends** as a major chart.

This should be a clean, modern multi-series line chart.

Inside the chart container, add pill-style metric selectors:

* `Time In`
* `Time Out`
* `Late`
* `Missing Out`

Multiple pills can be active simultaneously.

For example:

`[Time In] [Time Out] [Late] [Missing Out]`

The chart should show the selected metrics as separate series.

The admin can turn individual metrics on or off using the pills.

Do not force all four series to remain visible.

The chart should use visually distinguishable series while maintaining the existing application's clean dashboard aesthetic.

---

# 7. Date Filter for Daily Scan Velocity & Movement Trends

Place the date filter **inside the chart container**, not above the page.

The chart should have a default time range.

Default:

`Last 3 Months`

If insufficient/no data exists:

`School Year`

Allow the admin to manually change the date range.

Possible controls can include:

* Date range
* Preset period
* Custom date range

The chart should never initially be blank because a date has not been selected.

---

# 8. Section Attendance & Late Entry Breakdown

The existing:

`Section Attendance & Late Entry Breakdown`

should be made more visual.

Instead of relying primarily on a plain table, use a combination of:

* Chart/graph
* Supporting table

The chart should visually communicate differences between sections.

The table should provide the exact values behind the visualization.

Place this in the same horizontal row as:

`Daily Scan Velocity & Movement Trends`

on desktop-sized layouts.

The two containers should have balanced widths and aligned heights where practical.

---

# 9. Other Analytics Containers

Apply the same principle to the other analytics sections.

Where a section currently relies heavily on a table, improve the presentation by combining:

`Visual Chart + Supporting Table`

when the data is suitable for visualization.

The objective is to make patterns immediately understandable without removing the detailed tabular information.

Keep the existing data and business meaning intact.

---

# 10. Multiple Late Arrivals

Create/maintain a dedicated section for students with repeated late arrivals.

This should be useful for administrative follow-up.

The system should identify patterns such as:

* Multiple late arrivals
* Consecutive late arrivals
* Repeated lateness within the selected period

Because students attend approximately 5 days per week, repeated lateness within a week should be treated as an administrative attention signal.

Do not hardcode a single arbitrary condition if the existing system already has a relevant rule/configuration. Use the application's actual attendance data.

---

# 11. Missing Time Out

Create an equivalent administrative monitoring section for **Multiple Missing Time Outs**.

The system should identify:

* Repeated missing Time Outs
* Consecutive missing Time Outs
* Multiple missing Time Outs within a week

For example, approximately 3 or more missing Time Outs within a week should be clearly surfaced as a repeated pattern requiring attention.

Again, use actual attendance records and existing business rules where available.

---

# 12. Same Row Layout for Follow-Up Tables

The:

`Multiple Late Arrivals Follow-Up Registry`

and:

`Multiple Missing Time Out Follow-Up Registry`

should be placed in the same horizontal row on desktop layouts.

Each should have its own compact table/list.

Both should provide access to the relevant administrative intervention/action.

---

# 13. Administrative Action Directives

Use the existing:

`Administrative Action Directives`

container as the primary location for administrative intervention actions.

The intervention functionality should be particularly visible in:

`Multiple Late Arrivals Follow-Up Registry`

and the new:

`Multiple Missing Time Out Follow-Up Registry`

The admin should be able to initiate an intervention directly from the relevant record.

Also provide intervention access for individual late/missing-out records where appropriate.

---

# 14. IN/OUT Intervention

The intervention system should follow the same general concept as the previously designed At-Risk intervention feature, but this is a separate use case.

This intervention is specifically for:

* Late Time In
* Repeated Late Time In
* Missing Time Out
* Repeated Missing Time Out
* Relevant IN/OUT attendance patterns

The scope is **School Admin**.

The intervention should not use academic risk information.

---

# 15. Intervention Recipients

The available recipients are:

* `Class Adviser`
* `Parent / Guardian`

The admin can select:

`[ ] Class Adviser`

`[ ] Parent / Guardian`

or both.

Multiple recipients should be supported.

The system must keep recipient routing specific to the selected student.

For example:

`Student A → Adviser A + Parent A`

must never become:

`Student A → Adviser B + Parent B`

---

# 16. Adviser Notification

The adviser message should be appropriate for an internal school notification.

It should inform the adviser about the student's IN/OUT pattern and request appropriate monitoring/follow-up.

Examples include:

* Repeated late arrivals
* Consecutive late arrivals
* Repeated missing Time Outs
* Consecutive missing Time Outs

The message should contain the actual student's relevant records/pattern.

---

# 17. Parent / Guardian Notification

The parent/guardian email should use a different message template from the adviser notification.

The tone should be informative and advisory rather than disciplinary.

The message can naturally use a Tagalog/English combination where appropriate, similar to the previously designed intervention messages.

For example, it can explain that the school is informing the parent/guardian about a repeated Time In or Time Out concern and politely ask them to monitor/remind the student.

The parent message should clearly communicate:

* Student name
* Relevant IN/OUT concern
* Relevant dates/counts
* Pattern observed
* Appropriate reminder/request for cooperation

Do not use the academic At-Risk template for this.

Create a dedicated IN/OUT intervention template.

---

# 18. Intervention Template Must Match the Situation

The generated message must reflect the actual reason for intervention.

Examples:

### Repeated Late Arrival

The message should discuss repeated late Time In records.

### Consecutive Late Arrival

The message should mention the consecutive pattern.

### Repeated Missing Time Out

The message should discuss missing Time Out records.

### Multiple Missing Time Out

The message should mention the number/pattern of missing Time Outs.

Do not generate one generic message for every situation.

---

# 19. Intervention Preview

Before sending an intervention, show the admin a preview of the exact message.

The intervention form should identify:

**Student**

* Student name
* Section
* Relevant IN/OUT information

**Reason**

Example:

`Repeated Late Arrivals`

**Pattern**

Example:

`4 late arrivals within the selected period`

**Recipients**

* Class Adviser
* Parent / Guardian

**Message Preview**

Show the exact message that will be sent.

If both recipients are selected and the templates differ, show the adviser version and parent/guardian version separately.

---

# 20. Intervention Form Design

Modernize ONLY the intervention form and its preview/review interface.

Do not redesign the entire IN and OUT Analytics page just for the intervention form.

The intervention form should be:

* Modern
* Clean
* Medium-compact
* Easy to scan
* Responsive
* Not excessively spacious

Use a compact card/modal/drawer style.

Organize it into clear sections:

`Student`

`IN/OUT Concern`

`Pattern / Evidence`

`Recipients`

`Message Preview`

`Actions`

Avoid unnecessarily large form controls and excessive whitespace.

---

# 21. Chart Layout

The overall analytics page should feel like a modern dashboard.

Keep charts clean and visually readable.

Avoid making every section look like a large card full of text.

Use:

* Clear chart titles
* Compact controls
* Inline filter controls
* Appropriate legends
* Clear tooltips
* Balanced spacing
* Consistent chart heights
* Supporting tables where useful

The chart controls should live inside their respective containers.

---

# 22. Important Layout Requirement

The page should conceptually follow this structure:

### Summary

`Summary Statistics`

### Analytics Row 1

`Daily Scan Velocity & Movement Trends`
+
`Section Attendance & Late Entry Breakdown`

### Analytics / Monitoring Row 2

`Multiple Late Arrivals Follow-Up Registry`
+
`Multiple Missing Time Out Follow-Up Registry`

### Administrative Actions

`Administrative Action Directives`

with intervention actions connected to the relevant late and missing-out records.

Use responsive behavior so the rows stack naturally on smaller screens.

---

# 23. Core User Flow

The admin should NOT have to configure the page before seeing analytics.

Initial flow:

`IN and OUT Analytics`

→ Dashboard immediately displays meaningful 3-month overview

→ If insufficient data, automatically use school-year data

→ Admin can independently filter individual charts/tables

→ Admin identifies repeated late/missing-out patterns

→ Admin opens the relevant record

→ Admin selects Class Adviser, Parent/Guardian, or both

→ System generates the appropriate IN/OUT intervention template

→ Admin previews the message

→ Admin sends the intervention

The overall experience should feel like an **active analytics and administrative monitoring dashboard**, not an empty report page waiting for filters.
