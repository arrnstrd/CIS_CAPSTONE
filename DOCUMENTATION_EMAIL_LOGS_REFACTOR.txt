2. BACKEND IMPLEMENTATION

LOCATION: app/Models/EmailLog.php

NEW QUERY SCOPES ADDED:
────────────────────────

a) scopeFilterByDateRange($query, $startDate, $endDate)
   Purpose: Filter logs between two dates (inclusive, end of day)
   Parameters:
     - $startDate: Carbon instance or string (parsed as Carbon)
     - $endDate: Optional, defaults to $startDate if not provided
   Usage: 
     EmailLog::filterByDateRange('2026-05-20', '2026-05-24')->get()
     EmailLog::filterByDateRange(Carbon::parse('2026-05-20'))->get()

b) scopeTodayOnly($query)
   Purpose: Filter logs created today only
   Usage: EmailLog::todayOnly()->get()
   Implementation: Calls filterByDateRange(Carbon::today(), Carbon::today())

c) scopeYesterdayOnly($query)
   Purpose: Filter logs created yesterday only
   Usage: EmailLog::yesterdayOnly()->get()
   Implementation: Calls filterByDateRange($yesterday, $yesterday)

d) scopeLast7Days($query)
   Purpose: Filter logs from last 7 days (inclusive, today to 6 days ago)
   Usage: EmailLog::last7Days()->get()
   Implementation: Calls filterByDateRange(Carbon::today()->subDays(6), today)

e) scopeFilterByStatus($query, $status)
   Purpose: Filter logs by single or multiple statuses
   Parameters:
     - $status: String ('sent', 'failed', 'pending') or array ['sent', 'failed']
   Usage:
     EmailLog::filterByStatus('sent')->get()
     EmailLog::filterByStatus(['sent', 'failed'])->get()

METHOD: index(Request $request)

NEW PRIVATE METHODS:

applyDateFilter($query, $dateFilter, $customStartDate, $customEndDate)
  Applies appropriate date scope based on filter type
  Handles 4 cases: today, yesterday, last_7_days, custom
  Defaults to 'today' if invalid filter provided
  
  Flow Chart:
  ├─ today → scopeTodayOnly()
  ├─ yesterday → scopeYesterdayOnly()
  ├─ last_7_days → scopeLast7Days()
  ├─ custom → scopeFilterByDateRange(start, end) if dates provided
  └─ default → scopeTodayOnly()

getFilteredStatistics($query)
  Clones the base query and counts statistics
  IMPORTANT: Uses clone to avoid modifying pagination query
  
  Returns array:
  {
    'total': int,    // Total count of all filtered logs
    'sent': int,     // Count with status = 'sent'
    'failed': int,   // Count with status = 'failed'
    'pending': int   // Count with status = 'pending'
  }

OPTIMIZATION NOTES:

- Use whereBetween for date ranges (database-level filtering)
- Eager load student relationship to prevent N+1 queries
- Search combines whereHas for related models with orWhere for direct fields

REUSABLE PATTERN 1: Date-Based Filtering
─────────────────────────────────────────

Available Methods:
  EmailLog::todayOnly()
  EmailLog::yesterdayOnly()
  EmailLog::last7Days()
  EmailLog::filterByDateRange($startDate, $endDate)

Usage Examples:

// Example 1: Get all failed emails from today
$todaysFailed = EmailLog::todayOnly()
    ->where('status', 'failed')
    ->get();

// Example 2: Count sent emails from last week
$lastWeekSent = EmailLog::last7Days()
    ->where('status', 'sent')
    ->count();

// Example 3: Custom date range with search
$customRangeLogs = EmailLog::filterByDateRange('2026-05-01', '2026-05-15')
    ->whereHas('student', function($q) {
        $q->where('first_name', 'like', '%John%');
    })
    ->get();

// Example 4: Combine multiple scopes
$weekPendingEmails = EmailLog::last7Days()
    ->filterByStatus('pending')
    ->count();


REUSABLE PATTERN 2: Statistics Calculation
───────────────────────────────────────────

For similar statistics anywhere in the app:

$baseQuery = EmailLog::with('student')
    ->todayOnly()
    ->where('scan_type', 'IN');

// Clone and count each status
$stats = [
    'total' => $baseQuery->count(),
    'sent' => (clone $baseQuery)->where('status', 'sent')->count(),
    'failed' => (clone $baseQuery)->where('status', 'failed')->count(),
    'pending' => (clone $baseQuery)->where('status', 'pending')->count(),
];

KEY PRINCIPLE: Clone the query before final counting to preserve filters


REUSABLE PATTERN 3: Dynamic Filter Application
───────────────────────────────────────────────

Generic filter application pattern used in controller:

private function applyFilter($query, $filterType, $filterValue)
{
    return $query->when($filterValue && $filterValue !== 'all', function($q) use ($filterType, $filterValue) {
        // Apply filter logic
        $q->where($filterType, $filterValue);
    });
}

This pattern can be extended to:
- Add new status types without changing base query
- Filter by additional fields (add custom_field dropdown, add to when())
- Create new filter dropdowns easily


EXTENDING QUERY SCOPES:
Suppose you need to add a "Last 30 Days" filter:

1. Add to EmailLog.php:
   public function scopeLast30Days(Builder $query)
   {
       $startDate = Carbon::today()->subDays(29);
       return $query->filterByDateRange($startDate, Carbon::today());
   }

2. Update controller applyDateFilter():
   case 'last_30_days':
       return $q->last30Days();

3. Add option to Blade dropdown:
   <option value="last_30_days">Last 30 Days</option>

CURRENT FILTER STRUCTURE:

Request Parameters:
┌─────────────────────┬──────────────────────────┬──────────────┐
│ Parameter           │ Possible Values          │ Default      │

  public function scopeMonthToDate(Builder $query)

Step 2: Update controller applyDateFilter() switch statement

  </option>

That's it! No other changes needed. The withQueryString() on pagination 
automatically preserves this parameter.

  This affects sorting, so add to controller

Step 2: Update index() method
  Add parameter: $sortByStatus = $request->input('sort_status', false)
  
  Update the orderBy():
  $emailLogs = $baseQuery

          $q->orderByRaw("CASE WHEN status='failed' THEN 0 WHEN status='pending' THEN 1 ELSE 2 END");

      ->orderBy('last_attempt_at', 'desc')
      ->paginate(25)

      </label>
  </div>

10. DEBUGGING GUIDE
================================================================================

COMMON ISSUES AND SOLUTIONS:
─────────────────────────────

ISSUE 1: Statistics don't match actual emails
────────────────────────────────
Symptom: Card shows "Sent: 5" but table shows 7 sent emails
Cause: Statistics calculation error or pagination offset
Solution:
  1. Check getFilteredStatistics() in controller
  2. Verify clone() is used for each count
  3. Check if filters are applied correctly
  4. Log: dd($emailCounts, $emailLogs->count())

Debug code:
  $baseQuery = EmailLog::todayOnly();
  $emailCounts = $this->getFilteredStatistics($baseQuery);
  $total = $baseQuery->count(); // Should match $emailCounts['total']
  dd(compact('emailCounts', 'total'));


ISSUE 2: Date filtering not working
────────────────────────────────────
Symptom: Selecting "Yesterday" still shows today's emails
Cause: Timezone issue or incorrect date calculation
Solution:
  1. Check app timezone in config/app.php
  2. Verify Carbon::today() uses correct timezone
  3. Check database timestamp type (DATETIME vs TIMESTAMP)
  
Debug code:
  dd([
    'app_timezone' => config('app.timezone'),
    'today' => Carbon::today(),
    'yesterday' => Carbon::yesterday(),
    'query_range' => [
        'start' => Carbon::today()->startOfDay(),
        'end' => Carbon::today()->endOfDay()
    ]
  ]);


ISSUE 3: N+1 Query Problem
──────────────────────────
Symptom: Page loads slowly with many logs
Cause: Querying student for each log row
Solution:
  1. Verify with('student') in index() query
  2. Check Blade doesn't call additional queries
  3. Use Laravel Debugbar to view query count

Debug code:
  DB::enableQueryLog();
  // Run controller logic
  dd(DB::getQueryLog());
  // Should see: 1 query for EmailLog + 1 for students (not 1 + n)


ISSUE 4: Custom date range not applying
────────────────────────────────────────
Symptom: Custom dates selected but ignored
Cause: Validation or parameter not passed
Solution:
  1. Check custom_start_date and custom_end_date in request
  2. Verify date format is YYYY-MM-DD
  3. Check applyDateFilter() handles custom case

Debug code:
  dd([
    'date_filter' => request('date_filter'),
    'custom_start' => request('custom_start_date'),
    'custom_end' => request('custom_end_date'),
  ]);


ISSUE 5: Retry button not showing for failed emails
─────────────────────────────────────────────────────
Symptom: Status is "failed" but no retry button
