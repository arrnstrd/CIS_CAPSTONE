## CONTEXT

This is a Laravel/PHP school attendance system with QR-based attendance.

We currently have `session_type` stored independently in:

- `enrollments.session_type`
- `teaching_assignments.session_type`
- `attendance_logs.session_type`
- `schedule_configs.session_type`

The intended architecture is to make:

    sections.session_type

the source of truth for the session assigned to a section.

Therefore:

    Section
       │
       ├── Enrollment
       │      └── derives session_type from Section
       │
       └── TeachingAssignment
              └── derives session_type from Section

However:

    attendance_logs.session_type

MUST REMAIN.

It represents the session type captured at the time an attendance event was recorded. It is historical/snapshot data and must not be removed or rewritten.

Likewise:

    schedule_configs.session_type

MUST REMAIN.

It is the lookup dimension used by the schedule resolver.

# TARGET ARCHITECTURE

The desired relationship is:

    sections.session_type
          │
          ├── enrollments.section_id
          │
          └── teaching_assignments.section_id

Therefore Enrollment and TeachingAssignment should no longer be independent owners of session type.

The eventual target is:

    Section owns session_type
    Enrollment derives session_type from Section
    TeachingAssignment derives session_type from Section
    AttendanceLog stores a snapshot of session_type
    ScheduleConfig uses session_type as its schedule dimension
